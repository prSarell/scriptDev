CORRECTIVE BLENDSHAPE TOOL — DEVELOPMENT PLAN
===============================================
Last updated: 2026-06-17


CURRENT STATE
-------------
The tool is functional for the core workflow:
  - Step 1: capture pose (creates sculpt mesh + pose reference)
  - Step 2: bake corrective (extracts delta, creates pre-skin blendShape target,
    wires SDK driver — either multi-driver setRange/multiply network or single
    custom attribute SDK)
  - Update Target: rewrites target vertex data directly to ipt/ict via mel.eval
  - Delete Target: removes a target from the corrective blendShape node
  - Target list: shows all existing targets on the loaded mesh
  - Driver modes: Auto (captures active blendShape weights) and Custom Attribute
  - Session recovery: reconnects sculpt/poseRef meshes on mesh load
  - Duplicate name guard: catches alias conflicts before bake
  - Sculpt/PoseRef picker buttons for manual reconnection

Delta extraction uses per-vertex skin-matrix inversion (maya.api.OpenMaya):
  For each vertex i:
    W_i = Σ( weight_ij * bindPreMatrix_j * worldMatrix_j )
    preskin_target[i] = sculpted[i] * W_i⁻¹
  This is exact regardless of joint rotation. Falls back to raw sculpted
  positions when no skin cluster exists.

The pose reference mesh (dup_b) is still created in Step 1 as a visual
reference but is no longer required for the bake or update math paths.

FUTURE CONSIDERATIONS
  - Dual quaternion skinning: current implementation assumes linear (classic)
    skinning. Dual quaternion blending uses a different formula and would
    need separate handling. Worth adding a check/warning.
  - Multi-joint pose readers (out of scope for v1)
  - Left/right mirroring (out of scope for v1)
  - In-betweens (out of scope for v1)
  - Consider removing poseRef from workflow entirely if testing confirms
    it has no practical use after the matrix inversion switch.
