Date: 2026-06-06

--- TOOL 1: Metahuman Facial Transfer (Port) ---

Repo cloned: scriptDev/metahuman_facial_transfer/
Source: https://github.com/swnolan/metahuman_facial_transfer

Status: Blocked in Maya 2025 — both metahuman_api.py and metahuman_facial_transfer.py
open with `import pymel.core as pm` and raise ImportError immediately.

Port plan (tomorrow):
- Create metahuman_api_25.py and metahuman_facial_transfer_25.py
- ~50 PyMEL substitutions, all have direct maya.cmds equivalents
- Controller.train_control_expressions() is most complex piece — uses PyMEL
  attribute objects (.attr(), .set(), .get(), .isFreeToChange(), .isKeyable())
- Namespace handling in _set_metahuman_name() uses pm.Namespace objects
  -> replace with cmds.ls(..., type='embeddedNodeRL4') and string namespace parsing
- pm.mel.FBXImport*() calls -> mel.eval('FBX...') strings
- Reference file management (.referenceFile().remove()) -> cmds.file(rfn, removeReference=True)
- PySide6 import already correct for Maya 2025 (tries PySide6 first)
- retarget_metahuman_level_sequence is explicitly locked to specific Maya versions,
  none of which include 2025 — only the Animation Sequence path matters

Accuracy note: The original tool's Controller.train_control_expressions() method exists
specifically for accuracy. It dynamically discovers which expression drives which control
by setting controls to their limits and measuring what changes on CTRL_expressions.
Do NOT replace this with a hardcoded lookup table — the complexity is load-bearing.

--- UPDATE 2026-06-07: Port complete, headless validation passed ---

metahuman_api_25.py and metahuman_facial_transfer_25.py are done (maya.cmds + mel,
PySide6, no PyMEL). Added strip_namespace()/get_namespace() helpers to replace
pm.Namespace. Fixed a latent bug from the original: blend_weighted_nodes was never
appended to, leaving orphan blendWeighted nodes after a transfer — now fixed.

Validated headlessly via mayapy against scoutPrevis013/scene_EYES_FIX_PREVIS_FINAL_003.mb
(opened read-only, not saved): found both embeddedNodeRL4 nodes correctly,
get_face_controls() -> 173 controls, get_controllers() -> 160 valid trained controllers,
zero errors. Confirms train_control_expressions() works correctly ported to cmds.

Still untested: FBX import/export/retarget + the UI itself (need an Unreal FBX export
and an interactive Maya session — UI can't be driven headlessly).

To launch the UI, paste into the Maya Script Editor (Python tab) with a Metahuman
scene open:

    import sys
    sys.path.insert(0, r'C:\Users\patsa\OneDrive\Documents\maya\scriptDev\metahuman_facial_transfer')

    import metahuman_facial_transfer_25
    metahuman_facial_transfer_25.UI()

If you edit the modules and want to re-launch without restarting Maya:

    import importlib
    importlib.reload(metahuman_api_25)
    importlib.reload(metahuman_facial_transfer_25)
    metahuman_facial_transfer_25.UI()

Golden path to test: select anything on the Metahuman -> "Set Current Metahuman -->"
-> "Select Facial Controls" / "Reset Facial Controls" -> "Import FBX Animation
Sequence File..." (with an Unreal FBX export) -> "Export Facial FBX".


--- TOOL 2: Blendshape Baking Pipeline ---

Status: BUILT (2026-06-10) — untested in Maya, ready for in-scene test.
Files: rigDev/mh_bs_bake/mh_bs_bake_api.py + mh_bs_bake_ui.py

Launch in Maya Script Editor (Python tab) with a Metahuman scene open:

    import sys
    sys.path.insert(0, r'C:\Users\patsa\OneDrive\Documents\maya\scriptDev\rigDev\mh_bs_bake')
    import mh_bs_bake_ui
    mh_bs_bake_ui.show()

Workflow:
    1. Open a Metahuman scene with face controls visible
    2. Set namespace (or leave ':' for root)
    3. Click Auto to detect the face mesh (head_lod0_mesh / Face_mesh)
    4. Phase 1 — Bake Single Shapes: creates mh_bs_base + mhBsRig blendShape,
       wires all weights to controls via SDK
    5. Phase 2 — Find & Apply Correctives: enumerate all positive-direction pairs,
       compare vs original mesh, bake residual correctives, wire via combinationShape

Corrective math (proper residual, not just raw gt capture):
    corr_target[i] = neutral[i] + (gt[i] - bs_current[i])
    Result: neutral + (tA-neutral) + (tB-neutral) + (corr-neutral) = gt exactly

Corrective wiring: combinationShape inputs connect FROM the single-shape
blendShape weights (already 0->1 via SDK) — no extra remap nodes needed.

Expected: ~30-60 correctives, mouth corners / nasolabial / eye corners.
Phase 2 is O(N^2) on positive channels, safe to run overnight in mayapy.
